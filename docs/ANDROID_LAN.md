# НарядAI для Android — автоматическое подключение по Wi-Fi

## Быстрый запуск демо

1. Ноутбук и Android-телефоны подключите к одной обычной Wi-Fi-сети.
2. На ноутбуке откройте `Start-LAN.command` (macOS) или `Start-LAN.bat` (Windows). Альтернатива: в папке проекта выполните `npm run start:lan`.
3. Дождитесь строки **«Автообнаружение включено»**. Окно сервера оставьте открытым.
4. На телефонах установите `NaryadAI-LAN.apk` и откройте **«НарядAI Wi-Fi»**. Android может попросить разрешить установку из выбранного приложения. На Android 17 разрешите доступ к локальной сети.
5. Приложение найдёт ноутбук и откроет общую демо-смену. IP вводить не нужно. Если найдены несколько ноутбуков, на всех телефонах выберите один сервер.
6. На ноутбуке оставайтесь мастером. На телефоне нажмите **«Сменить роль»** и выберите исполнителя. Выдайте ему наряд: задание появится на телефоне, а действия исполнителя — на ноутбуке.

APK один для мастера, исполнителя, руководителя и администратора. Android 8.0 и новее; ARM, ARM64 и x86 совместимы, поскольку в APK нет нативных библиотек. Приложение использует установленный Android System WebView.

## Подготовка ноутбука

Нужен Node.js 22.13+ с npm. При первом запуске нового комплекта сервер установит зависимости; для этого нужен интернет. Если нет готовой папки `dist`, он также соберёт сайт. После установки зависимостей сервер, обнаружение и основные сценарии демо работают в локальной сети без облачного хостинга.

На macOS при ограничениях запуска файла используйте терминал: `bash Start-LAN.command`. Если система предлагает разрешить Node.js доступ к локальной сети, разрешите его. Встроенный firewall должен разрешать входящие подключения к этому демо-серверу.

Запуск без двойного клика:

```sh
npm run start:lan
```

Порт по умолчанию **8788**. Другой порт:

```sh
NARYADAI_LAN_PORT=8790 npm run start:lan
```

На ноутбуке откройте адрес, который сервер выводит в терминале, например `http://127.0.0.1:8788/demo`. Для телефона он выводит адрес локального интерфейса; APK обычно получает его автоматически.

## Что происходит автоматически

- Сервер публикует mDNS-сервис `_naryadai._tcp.local` после успешного запуска HTTP API.
- APK использует Android NSD, проверяет `/api/lan-discovery` и открывает `/demo`.
- Для первого подключения есть короткое ожидание, позволяющее обнаружить несколько серверов и предложить выбор.
- Последний выбранный адрес запоминается и проверяется при следующем запуске.
- Если страница сервера недоступна, приложение возвращается к поиску; неподключённое приложение повторяет поиск каждые 20 секунд.
- Кнопка **«Сервер»** сбрасывает выбор и запускает новый поиск.

Маркер приложения и протокол защищают от случайного подключения к другому типу сервера; они не являются криптографической проверкой владельца. Это демонстрация для доверенной локальной сети.

## Общая база и роли

Каждый телефон получает отдельную cookie-сессию и выбирает собственную роль. Все LAN-сессии используют одну демо-базу. Переключение роли на телефоне не переключает роль других участников.

LAN-режим включается только при сочетании `LOCAL_DEMO_NETWORK=true`, `DEMO_ONLY=true`, `WORKSPACE_MODE=false`. Обычный сайт продолжает создавать отдельное демо для каждого посетителя. Рабочие учётные записи через этот запуск недоступны.

Данные и фотографии хранятся на ноутбуке в `.wrangler/lan-state`; папка `.lan-runtime` содержит временную конфигурацию и адрес подключения. Сервер не загружает секреты из основной `.dev.vars`. Фотографии хранятся в локальной D1, облачный R2 не требуется. Остановка и перезапуск сохраняют общую смену.

## Возможности Android-оболочки

- Фотографии: системный выбор изображения или приложение камеры, через ограниченный временный URI.
- Excel: кнопка экспорта открывает системное окно сохранения `.xlsx`.
- Печать/PDF: системное окно Android; выберите «Сохранить как PDF» при наличии службы печати.
- Голосовой ввод: системный сервис распознавания Android. Доступность и распознавание без интернета зависят от установленных языков и сервиса телефона.
- Возврат, перезагрузка страницы, смена сервера.

HTTP в локальной сети не создаёт защищённый браузерный контекст: Web Push в фоне и браузерная камера QR-сканера в этом режиме не гарантируются. Для нарядов доступны уведомления внутри открытого приложения; фото можно сделать системной камерой. ИИ в демо использует прозрачную проверку правил и подтверждение мастером; внешняя модель не вызывается.

## Если сервер не найден

Обычный поиск не требует ввода IP. Гостевой Wi-Fi, изоляция клиентов, VPN и блокировка multicast могут мешать связи. Подключитесь к обычной общей сети и повторите поиск. У некоторых роутеров multicast блокируется, а HTTP работает: тогда нажмите **«Указать адрес вручную»** и вставьте адрес, показанный сервером.

Если устройства полностью изолированы друг от друга, ручной адрес тоже не поможет: нужно разрешить связь устройств или выбрать другую Wi-Fi-сеть. Ноутбук должен оставаться включённым, сервер — запущенным.

## Сборка APK из исходников

Приложение написано на Java с Android framework, без Gradle/AndroidX/npm-зависимостей. Нужны Python 3, JDK 21 и официальные Android SDK Platform 37.0 / Build Tools 37.0.0.

```sh
python3 android/build.py --sdk /path/to/sdk --java-home /path/to/jdk --output /path/to/NaryadAI-LAN.apk
```

Скрипт выполняет aapt2, javac, d8, zipalign, apksigner и проверяет подпись. Идентификатор приложения: `ai.naryad.lan`, версия `1.0.0`, minSdk 26, targetSdk 37.

Локальная подпись сохранена в `android/.signing/`; эта папка исключена из Git и комплектов ZIP. Сохраните её для выпуска совместимого обновления APK. Сборка из чистого ZIP создаст новую подпись: для замены установленного APK с другой подписью Android потребует сначала удалить старую установку.

Официальные инструменты: [Android SDK](https://developer.android.com/studio), [apksigner](https://developer.android.com/tools/apksigner), [D8](https://developer.android.com/tools/d8), [разрешение локальной сети](https://developer.android.com/privacy-and-security/local-network-permission).
