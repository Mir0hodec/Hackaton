# OpenRouter в НарядAI

Ключ хранится только на сервере. В браузер, APK, Git и ZIP-комплекты его включать нельзя. Фото внешней модели по умолчанию не передаются.

## Локальная общая смена

Создайте исключённый из Git файл `.dev.vars.lan-ai` в корне проекта:

```dotenv
AI_LAN_ENABLED=true
OPENROUTER_API_KEY=YOUR_OPENROUTER_KEY
OPENROUTER_MODEL=nvidia/nemotron-3-super-120b-a12b:free
```

Запустите `npm run build`, затем `npm run start:lan`. Если сервер уже работает, сначала остановите его и перезапустите: повторный Start-LAN не заменяет конфигурацию действующего сервера.

Start-LAN переносит в локальный runtime только этот ключ и настройки AI. Ключ записывается в серверный `.lan-runtime/.dev.vars` с правами 0600; в `wrangler.json` ключа нет. На Windows права доступа дополнительно определяются ACL пользователя. Набор данных и роли сохраняются после перезапуска. Ноутбуку нужен интернет для запросов к OpenRouter; телефоны подключаются к ноутбуку через обычную Wi-Fi-сеть.

Обычное изолированное демо не использует внешнюю модель. Она разрешена только явно включённой общей LAN-смене `demo:shared-lan:`. Для собственной рабочей среды задайте `AI_PROVIDER=openrouter`, `OPENROUTER_API_KEY` и `OPENROUTER_MODEL` в серверных секретах. Для этого локального подключения внешний деплой не требуется.

## Поведение помощника

Модель вызывает серверные инструменты: обзор смены, свободные исполнители, просроченные и активные наряды, отчёт за период, история оборудования, рейтинг исполнителя. Все инструменты только читают данные. Если модель пропускает вызов инструмента, сервер передаёт рассчитанный контекст и запрашивает ответ заново. Имена перед отправкой заменяются кодами сотрудников, контакты удаляются; имена подставляются обратно только в готовый ответ на ноутбуке.

Чат хранит шесть последних сообщений контекста. Цикл OpenRouter ограничен четырьмя шагами и 35 секундами; клиент ждёт не более 45 секунд. При ошибке ключа, лимита, провайдера или таймауте API возвращает ответ по данным системы с понятным уведомлением, а не 503. Модель и источник ответа обозначены в чате. Ошибки не содержат сырой ответ провайдера или ключ.

Общий адаптер также поддерживает JSON-сводки и проверку отчётов. Фото требуют отдельного разрешения `AI_PHOTOS_APPROVED=true`; локальный LAN-запуск не включает его автоматически.

По умолчанию используется бесплатная модель. Доступность и квоты зависят от OpenRouter; при нулевом лимите ключа платные модели не заработают. Выбор модели задаётся явно, платная подмена не выполняется.

## Проверки

`npm run test:quality` включает локальные тесты адаптера, цикла инструментов, обезличивания, изоляции публичного демо, разрешённого набора настроек, обработки 401/402/429/5xx и таймаутов. Эти тесты используют фиктивный ключ и подменённый `fetch`, не обращаются к внешнему API. Реальный запрос нужно отдельно проверить с собственным ключом в своей LAN-смене.

Официальная документация: [Chat API](https://openrouter.ai/docs/api/reference/overview), [вызов инструментов](https://openrouter.ai/docs/guides/features/tool-calling), [структурированные ответы](https://openrouter.ai/docs/guides/features/structured-outputs).
